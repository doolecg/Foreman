Foreman: what the audit found and what we do next

1 November 2026. I only read the code. Nothing was run or changed.

Read this first
  1. A normal chat starts with everything you have installed loaded. That is a lot of tokens before you type anything.
  2. Helpers start light, but only by accident.
  3. The "13k tokens" claim in the README is not measured anywhere.
  4. You can switch tools on and off per project for only three things. Skills and plugins have no switch.
  5. The plan is four steps: audit (done), rename, native project setup, then tidy the token handling.

1. What the audit found

  • Normal chats load everything. When you open a chat, Foreman starts Claude Code and adds a few extras on top. Claude Code still loads all your own plugins, hooks, settings and tools.
  • Helpers are light by accident. A helper skips your plugins and hooks only if it has a list of allowed tools. Nobody chose that on purpose. A helper with an empty list would load everything.
  • The 13k number is a guess. The README says helpers start near 13k tokens instead of over 100k. The code has no measurement for that. It might be right, but nothing proves it.
  • Switching tools per project barely exists. Only three tools can be turned on or off for a project: git, the browser and code search. Skills and plugins cannot be switched per project at all.
  • The code for this is messy. The same tool settings are stored four different ways and kept in step by hand. The list of tools is typed out in three separate places. The browser, code search and memory tools are each wired in by hand, and then wired in again, differently, for OpenCode.
  • Small things. Two different methods are used to switch off hooks for the same purpose. Orchestrator Mode's limits (three helpers at once, no helpers inside helpers) are only written as instructions to Claude, backed by one small hook.
  • What already works. There are daily limits on the app's own model calls, a cap on how big a chat can get, cache settings, and usage tracking against your plan limits. These stay.

2. The plan

  1. Audit. Done. This page.
  2. Rename. Operant becomes Foreman in the code, the screens and the installers. People who already use Operant keep their chats and settings.
  3. Native project setup.
    • A "Start new project" button, and a command that does the same.
    • You type what the project is. Foreman tidies up your prompt, looks around the folder and what it knows, and works out what the project needs.
    • It then turns on only those agents, tools, skills and plugins for that project, and writes the project files. It never touches your global setup and never deletes anything.
    • The list of what is available (the catalog) is installed into your .claude folder the first time. You can point Foreman at a different folder if you prefer.
  4. Tidy the tokens.
    • One catalog replaces the three typed-out lists and the four overlapping settings. Each entry says what it is, when it is needed and roughly what it costs.
    • One place decides what each chat or helper loads for a given project. The launch code just follows that decision.
    • Being light becomes a clear setting: full, project only, or strict. It no longer depends on whether a tools list exists.
    • Plugins get picked per project instead of all or nothing.
    • Foreman measures the real startup tokens for each setup and shows the cost per project. That either proves the 13k claim or corrects it.

I would do them in this order because steps 3 and 4 use the same catalog.

3. What I did not check

The helper that read the code only skimmed two of the chat files and did not follow every call. The line numbers it gave could be slightly off, so I will confirm each one before changing anything. I did not run the app.
