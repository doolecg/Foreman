Tokens reused

All colour comes from renderer/src/index.css, dark scheme. The light scheme should work by swapping the same names, so check it once on a phone. One thing to know: the stored theme is a neutral charcoal (--background #171717) with a warm orange accent, not brown. The warmth comes from --primary #d97757 and the grain overlay.

  • Ground --background, tab bar and tool rows --card, cards .surface (with --surface, --surface-border, --surface-line for rows inside), your bubbles --bubble, code --code, quiet buttons and options --accent, search and segmented control --secondary.
  • Text --foreground, secondary text --muted-foreground (6.4:1 on the ground, passes AA).
  • One action colour: --primary with --primary-foreground text. It is used only for the main button, the send button, the active tab icon and the inbox badge.
  • Status: --working (busy), --success (done, live), --warning (needs you, reconnecting), --destructive (errors only, never for the Deny button).
  • Motion: --m-ease, --m-select, --m-enter and the .m-press, .m-enter classes. Their reduced-motion fallbacks already exist.
  • Type: --font-sans (Figtree, bundled) everywhere, --font-mono only for file names, commands and diffs.
  • New, phone only: --tap 44px, --tap-big 52px, --pad 16px, --tabbar 64px.

The rules to build to

  1. Type sizes. Screen titles 28px weight 650. Body, messages and every input 16px (below 16px iOS zooms the page when you tap a field). Secondary lines 14px, meta 13px, nothing smaller. Lines 1.5 high.
  2. Touch targets. Every tap area is 44px or more, rows 64px. Approve, Deny, Allow once, Send answer and Connect are 52px high and at least half the width of the screen. Allow goes on the right, under the thumb; Deny on the left in the quiet style, never red, so a slip reads as a choice and not a warning.
  3. Bottom tab bar. Three tabs: Projects, Inbox, Agents. Icon with a word under it, a plain bar in --card with no blur and no floating pill. The Inbox badge shows the waiting count. The bar hides on pushed screens (a thread, a plan), where the composer takes the bottom.
  4. Safe areas. Set viewport-fit=cover. Pad the top bar with env(safe-area-inset-top), the tab bar and composer with env(safe-area-inset-bottom), and the sides with the left and right insets for landscape.
  5. Composer above the keyboard. Use height: 100dvh for the shell and the interactive-widget=resizes-content viewport key for Android. On iOS, listen to visualViewport resize and scroll, and lift the composer by the keyboard height. The text field grows to 6 lines, then scrolls. Model and context sit in one 13px line under it; the plus button opens a bottom sheet for images, slash commands and effort.
  6. Swipe back. Every screen change is a real history entry (pushState), so the browser's own edge swipe and the Android back button both work. Do not build a custom swipe on top, because it fights Safari's. The back arrow in the header does the same thing.
  7. Never swipe to approve. Approvals need a deliberate tap. A swipe in a list is too easy to trigger by accident when you are scrolling with one thumb.
  8. Offline and reconnecting. A banner under the header in --secondary with a --warning dot: "Reconnecting to DAYLE-PC. Your message will send when it's back." with a Retry button. Messages you send while it shows wait in the queue with a "waiting to send" line. Approve buttons are greyed while offline, so an answer is never lost. After 30 seconds the text changes to "Can't reach DAYLE-PC. Is the PC on and Tailscale running?"
  9. Reduced motion. Respect prefers-reduced-motion: no slide on screen changes (an 80ms fade instead), no pulsing dots, no moving graph links. Use the existing useMotionAllowed pattern from GraphView.
  10. Lock screen. No project names, counts or thread titles before the token passes. The token field uses autocomplete="off", autocapitalize="off", spellcheck="false", 16px text and a Paste button. A wrong token shakes nothing; it shows one line under the field: "That token didn't work. Check it on the PC." "Remember this phone" stores the token so the phone skips this screen next time.
  11. Approvals in a thread. When something is waiting and you have scrolled up, a 44px "Needs you" strip in --warning tint sits under the header; tapping it scrolls to the card. Answered cards collapse to one grey line, the same as desktop.
  12. Tool rows. One 44px line each: status, verb, the file in mono, cut off with an ellipsis. Tap to open the full output in a bottom sheet. Runs of five or more tools fold into "Read 6 files" with a count.
  13. Graph on the phone. The Compact layout, cards at full width, the council as three small cards in a row, the link drawn as one line down the left gutter that lights from the working card. Card names are sentence case at 15px, not the desktop's small spaced capitals, because the phone rules ban those. If you want the desktop look kept, that is a one-line change.
  14. States. Empty inbox: "Nothing waiting. Claude will ping the badge when it needs you." Empty project: "No threads yet" with the New thread button. Loading: the list keeps its last data and shows a thin progress line at the top, no grey placeholder bars.

Components to build, and what to reuse

  1. PhoneShell: the 100dvh frame, safe-area padding, history-backed routing, tab bar. New. Shown when the window is under 600px wide or opened from the remote address.
  2. TabBar: three tabs and the inbox badge. New, small. The badge count comes from the same pending items ConversationList already finds.
  3. ProjectList: projects with their threads, search, the "needs you" line. Reuse the thread data and status dots from the desktop sidebar; new layout.
  4. PhoneChatView: header, messages, composer. Reuse ConversationList.tsx and ItemViews.tsx for the messages, with a phone class that raises sizes to the rules above. Reuse Composer.tsx logic (send, queue, stop, images, CommandMenu.tsx) inside a new phone layout; the menus become bottom sheets.
  5. Prompt cards: reuse PermissionCard, QuestionCard and PlanCard from PromptCards.tsx and their chatActions.permission calls as they are. Add a phone variant of the button row: two 52px buttons in a grid, Always allow as a full-width text button below. Number keys stay for desktop only.
  6. ToolRow and ToolSheet: reuse the tool item data from ItemViews.tsx; the sheet shows the full output or DiffBlock.
  7. InboxView: all waiting permissions, questions and plans across projects. New list; each item renders the reused prompt cards with a project and age line on top.
  8. AgentsView: GraphAtWidth from mods/agents/GraphView.tsx with size forced to compact. Change only the card text sizes on the phone (15px names, 14px detail) and make each card a 44px+ button that opens its thread.
  9. ConnectionBanner: the reconnecting and offline banner. New. Reuse the toast motion tokens for its entrance.
  10. LockScreen: token entry, paste, remember. New. Needs a desktop side: Settings, then Phone access, showing the token and a "Forget all phones" button.
  11. BottomSheet: one shared sheet for composer extras, tool output and thread options. Reuse the .m-surface motion with data-side="bottom".
