Project run scripts (like T3 Code)

Planned for Saturday 7 November 2026. Branch: a new dev-4.4.0. Status: plan only, nothing built, waiting for your go.

Read this first

  1. A project gets a list of named scripts (for example "Dev", "Test", "Build"). One click runs one.
  2. Scripts live in the project, so each project has only the ones it needs (pillar 1).
  3. Nothing runs by itself. Only a click runs a script. Auto-run is left out of version 1.
  4. Four decisions for you are in section 6. I have picked a default for each, so you can just say "go".

1. What you get

  • A "Scripts" button in the chat header with one entry per script, plus a small editor to add, rename, reorder and delete them.
  • Each script has a name, a command, an optional folder (default: the project root) and an optional shortcut key.
  • Running a script shows live output in a panel, with a running mark and a Stop button. Stop ends only the process Foreman started, by its PID.
  • The run configs Foreman already reads from .run/ (Main Run, Dev Run) can be imported as a starting list, so you do not retype them.

2. What T3 Code does (from memory, not checked)

As I remember it, T3 Code keeps per-project script buttons in the header, each with a name, an icon, a command and a keybinding, and it can run one automatically when a new worktree is made. I have not looked at it this week. Step 1 below confirms it before we copy anything.

3. Where the data lives

In one project file, .foreman/scripts.json. This follows the rule that setup and project features only write project-level files and never touch global config. Foreman never deletes the file.

4. Saturday steps (one at a time, each with a check)

5. How you test it

  1. Open a project and click Scripts, then add "Dev" with command npm run dev.
  2. Click it. Output appears, the mark shows running. Click Stop. The mark clears and the process is gone from Task Manager.
  3. Click Import from .run. Main Run and Dev Run appear in the list.

6. Decisions for you (my pick first)

  1. Where output shows: a panel beside the chat (my pick), or a tab in the existing terminal.
  2. Run on new worktree: leave out of version 1 (my pick), or build it now.
  3. Same script twice: block the second click (my pick), or allow several.
  4. Icons: a small fixed set to choose from (my pick), or none.

7. Out of scope

  • Auto-run on open, on save or on a schedule.
  • Scripts that need secrets. Nothing is read from .env.
  • Running scripts on a remote machine.

8. Risks

  • A script can do anything the command does. The project file is plain text, so a cloned repo could carry a harmful script. Mitigation: no auto-run, and the command is shown in full before the first run of any script that came from a file you did not write.
  • Windows process trees: stopping a script must end its children too. Step 3 has a test for this.
